## GPIO: Simple Input

Q3: Explain the lines of code used to setup the button.
Here is how we set up the button in our code:
gpio_init(BUTTON_PIN); gets the specific pin ready to be used.

gpio_pull_up(BUTTON_PIN); turns on the internal pull-up resistor. This makes the pin read as a 1 (idle) when the button is left alone, and a 0 when the button is pressed.

## GPIO: Interrupts

Q5: Explain the lines of code used for setting up the interrupt handler (the code that runs when an interrupt happens)
Looking at the written GPIO_Interrupts.c code, to handle the interrupt signals, we simulated edge detection inside our main polling loop. We set it up by creating variables to track the state:
bool last_pressed = !gpio_get(BUTTON_PIN); stores the initial state of the button before the loop starts.
bool pressed = !gpio_get(BUTTON_PIN); stores the current state of the button.
int rising_edge = 0, falling_edge = 0; creates variables to keep track of how many times the button state changes.

Q6: Explain the code in the interrupt handler (the code that's actually run when an interrupt happens).
Our simulated "handler" is the if (pressed != last_pressed) block inside the loop, which triggers only when a real instantaneous change happens:
Inside this block, we check if (pressed) to see if the button just went down. If pressed is true, we add 1 to the rising_edge counter.
If false (else), it means the button was just released, so we add 1 to the falling_edge counter. Therefore, as the counters only update when changes occur in the state of the button, the process of updating rising_edges and falling_edges behaves with interrupt handling. Once the counters are updated, we finally set last_pressed = pressed; so the program is ready to catch the next change.

## GPIO: Simple Outputs

Q8: Justify the circuit and it's impact on the power/voltage/current limits of the Pico.  That is, provide clear evidence/proof that the way the LED is connected is within the limits of the Pico.
The Pico's GPIO pins output 3.3V. A standard red LED typically requires a forward voltage of about 1.8V to 2.0V to turn on. According to Ohm's law (V = I * R), we can calculate the current. The voltage dropping across our provided 220 Ohm resistor is the remaining voltage: 3.3V - 1.8V = 1.5V.
So, 1.5V / 220Ohm = ~0.0068 Amps, or 6.8 milliamps (mA).
The RP2350 datasheet shows that a single GPIO pin can safely source around 12mA of current. 

Q9: Imagine you want to connect more LEDs.  Will power/voltage/current limits be an issue?  If so, how may you overcome any limitations?
Yes, it will definitely be an issue. While one pin can handle 6.8mA, the Pico's chip has a total maximum current limit for all GPIO pins combined (often around 50mA total).
To overcome this, we can use a transistor (like a MOSFET). Instead of powering the LEDs directly from the GPIO pins, we would connect the LEDs directly to the main power supply through the transistor. The Pico's GPIO pin would only need to send a tiny, low-current signal to the transistor to flip it "on" or "off" like a switch
